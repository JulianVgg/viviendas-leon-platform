# AI-01.2 — Integración del servicio de IA

**Prerequisito:** AI-01.1 aplicado y pruebas correctas. Este cambio **no crea aún la interfaz** (AI-01.3).

## Componentes

- `apps/api/src/modules/ai/analysis.service.ts`: autorización, consolidación de contexto, cupo y generación.
- `analysis.client.ts`: solicita análisis a `POST https://api.openai.com/v1/responses` mediante `fetch` nativo de Node; `store: false`, salida JSON estricta y timeout de 25 s.
- `analysis.schema.ts`: formato de resumen/hallazgos/riesgos/recomendaciones/limitaciones y validación local de referencias.
- `analysis.quota.ts`: limita solicitudes con transacción PostgreSQL y `pg_advisory_xact_lock` por día.
- `analysis.routes.ts`: endpoint institucional autenticado.
- `prisma/migrations/20261104160000_ai012_limite_consumo`: tabla `analisis_ia_solicitud` **sin contenido del análisis**.

## Configuración backend (`apps/api/.env` privado)

```ini
# Obtener desde https://platform.openai.com/api-keys
OPENAI_API_KEY=tu_clave_privada
# Modelo de bajo costo, compatible con Responses API y Structured Outputs
OPENAI_ANALYSIS_MODEL=gpt-5.6-luna
AI_DAILY_USER_LIMIT=3
AI_DAILY_GLOBAL_LIMIT=30
```

No subir `.env` a GitHub, y no colocar la clave en `VITE_*`. Sin `OPENAI_API_KEY` el endpoint devuelve `503 AI_NOT_CONFIGURED`; no genera costos. El modelo necesita crédito de API **independiente de ChatGPT**. Los límites son de **solicitudes, no un tope monetario garantizado**; usar controles de presupuesto y prepago en OpenAI Platform. Las solicitudes fallidas también consumen cupo conservadoramente. Se aplican a múltiples instancias porque el conteo se almacena en PostgreSQL. Los límites de configuración tienen un máximo permitido de 20 por usuario y 200 global.

## Endpoint (AI-01.3 lo consumirá)

`POST /api/v1/dashboard/analisis` con sesión vigente de **Dirección o Coordinación**, y cabecera `Content-Type: application/json`.

```json
{ "meses": 6, "comunidadId": 2, "responsableId": 7 }
```

`comunidadId` y `responsableId` son opcionales; `meses` debe ser 3, 6 o 12. El backend **no acepta** que el cliente suministre métricas, prompts, modelos o instrucciones. Obtiene toda la información desde AI-01.1 y PostgreSQL.

Respuesta `200`: `{ "resultado": { "resumen": "...", "hallazgos": [...], "riesgos": [...], "recomendaciones": [...], "limitaciones": [...] }, "metadata": { "version": "AI-01.2/v1", "generadoEn": "...", "periodos": { ... }, "filtros": { ... }, "modelo": "...", "indicadoresPermitidos": [ ... ] } }`.

Respuestas esperadas: `400` filtros inválidos; `401` sin sesión; `403` rol sin permiso; `429` cupo diario; `503` sin clave, error externo o consulta indisponible; `502` salida inválida. Ningún error divulga claves, prompts ni datos individuales.

## Reglas y alcance

- Métricas agregadas exclusivamente, sin nombres de familias, teléfonos, correos ni fotografías.
- Cada conclusión y recomendación lleva claves de indicadores de una lista blanca, validadas **después** de recibir respuesta. No se aceptan referencias inventadas.
- Envíos a OpenAI usan `store: false`, pero hay que revisar el acuerdo de privacidad y retención del proveedor antes de producción.
- Las respuestas no se guardan en PostgreSQL: solo `usuario_id`, modelo, estado, fecha y tokens de uso.
- La IA no puede consultar tablas arbitrarias ni modificar datos, ni ejecutar herramientas o acciones.
- No garantizar verdad solo por el formato JSON: el personal debe contrastar los hallazgos con sus indicadores.
- No entrenamos un modelo propio ni generamos informes al abrir cada página; se genera **solo bajo demanda**.

## Pruebas manuales propuestas

1. Sin clave: `503 AI_NOT_CONFIGURED`; no se consulta OpenAI ni se consume cupo.
2. Cuenta técnica: `403`, sin consultas institucionales ni llamadas externas.
3. Dirección: enviar solicitud, comprobar cuatro secciones y referencias permitidas.
4. Repetir cuatro veces el mismo día: con límite por usuario 3, el cuarto intento debe responder `429`.
5. Verificar que un error/timeout de OpenAI no interrumpe `/api/v1/dashboard/resumen`.
6. Consultar `SELECT usuario_id, modelo, estado, tokens_entrada, tokens_salida, creado_en FROM analisis_ia_solicitud ORDER BY creado_en DESC LIMIT 20;`.
7. Comprobar que las métricas de kg y unidades son distintas y que el texto no confunde datos futuros programados con visitas realizadas.
